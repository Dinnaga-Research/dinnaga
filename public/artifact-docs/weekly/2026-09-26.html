Multi-Agent Coordination via Shared Broadcast Logs

Surfaced repeatedly in the arxiv-prospector triage, with a dedicated 'Global Workspace/Baars' committee voice specifically reading papers for this pattern.

  • 'Verified progress sharing' — agents adopt a discovery only after a verifier checks it — provably beats parallel-but-isolated search, with an exponential separation proven for the min-of-sums vs. sum-of-minima case.
  • Concrete coordination primitives recur across papers: atomic `mkdir` for slot claiming, an append-only shared log, and a separate 'disconfirmations' log to stop agents from re-exploring dead ends.
  • The dominant failure mode is 'herding' — premature convergence on a shared answer before enough independent exploration has happened; an explicit anti-herding prompt is one mitigation.
  • These broadcast/spotlight/competition-for-access patterns map onto Global Workspace Theory's 'broadcast wins attention' model, but gated on verifier correctness rather than salience.

Self-Evolving Agent Skill and Procedural-Memory Systems

Several triaged papers this week proposed treating an agent's own skill library or harness code as the thing that learns, rather than retraining the underlying model.

  • A frozen-model skill bank can still improve materially through paired 'widen' (new skills) and 'deepen' (refine existing skills) operations, validated with a matched, order-randomized replay gate instead of absolute scores.
  • Cold-start skills authored purely from documentation don't help until they've been hardened against real graded traces — direct experience beats doc-derived priors.
  • Making the harness/skill code itself the persistent, learnable artifact let a small model match or beat a much larger one on long-horizon tasks while cutting inference cost.
Further reading
  • Agent Skills for Large Language Models: Architecture, Acquisition, Security, and the Path Forward
  • self-improving-skills: Hermes Agent-style self-improvement for Claude Code

Deterministic Verification and Admission Gates for Agents

A recurring 'harness-engineering' theme this week: papers arguing agent outputs should be checked by hard-coded, non-LLM control logic before being trusted or acted on.

  • Keep an agent's memory or self-reported claims 'advisory' until they've been converted into an executable, deterministic check — never let a model's self-report be the final gate.
  • Admission gates work best as read-only, pre-execution checks against explicit policy rules that either allow or reject a call with a structured reason, without themselves invoking another model.
  • Durable ledgers with atomic per-stage replay let a long-running agent pipeline recover mid-crash without redoing already-verified work.
Further reading
  • A Deterministic Control Plane for LLM Coding Agents
  • Agent Control Protocol: Admission Control for Agent Actions

Cost-Aware LLM Routing and Cascades

Multiple triaged papers targeted token-economy — routing most work to cheap models and escalating only on low confidence — echoing the operator's own cost-tiered agent-dispatch tooling.

  • Confidence-gated cascades (cheap model first, escalate only when a verifier or confidence check fails) can retain roughly 95% of frontier-model quality at 75-85% lower cost.
  • The generalizable lever isn't a smarter model — it's a better verifier or confidence signal deciding *when* to escalate.
  • Harness-level optimization (rewriting the surrounding scaffolding and prompts) can cut LLM call counts by 70-90%+ at equal-or-better task success, independent of any model swap.
Further reading

  • How to Cut LLM Token Costs in 2026: Routing, Caching, Compression, and the Right Model

Spotting Weak Empirical Rigor in AI Research Papers

Every daily triage ran a dedicated 'veracity' committee voice reading papers end-to-end for overclaiming; the same handful of red flags recurred across the whole week's batches.

  • The most common paper-sinking flaw is a proxy metric that doesn't actually correlate with the real target — e.g. an optimization objective the paper's own appendix shows has near-zero correlation with ground truth.
  • Headline numbers reported without seeds, confidence intervals, or significance tests, or drawn from single (n=1) runs, get capped as 'thin' even when the underlying idea is sound.
  • Fabricated or placeholder table values (explicitly labeled as needing future validation) are treated as an automatic block, not just a caveat.
  • Self-reproduced baselines, single-model/single-seed evaluations, and confounded before/after comparisons are the recurring gap between a paper's framing and its actual evidence.

  • AAAI Reproducibility Checklist

White-Box Detection of Concealed Knowledge and Deception in LLMs

A standout paper this week adapted the forensic Concealed Information Test to probe whether a model internally 'knows' something it won't state outright.

  • Borrowing the forensic Concealed Information Test: present the true detail hidden among plausible decoys and look for a stronger internal (activation-level) response to the item the model recognizes — no output-text admission needed.
  • The method distinguishes a model 'hiding' knowledge (present internally, just not surfaced) from true 'erasure' (not represented at all) — a distinction with real safety implications.
  • This class of technique is inherently white-box (needs residual-stream/activation access), so it cannot be run against closed, hosted frontier models — a real limitation for anyone working only through an API.
Further reading
  • A Lie Detector Test for Language Models: Reading Knowledge a Model Won't Reveal
  • Liars' Bench: Evaluating Lie Detectors for Language Models
  • How to Catch an AI Liar: Lie Detection in Black-Box LLMs
