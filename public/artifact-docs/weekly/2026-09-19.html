Managing a Multi-Machine AI Harness Research Fleet

The operator asked how to approach managing three tailnet-connected machines, each running a different slice of harness research, without the surface area becoming unmanageable.

  • An 'agent harness' (or scaffold) is the software layer around a model — tool dispatch, memory, sandboxing, context management — and swapping harnesses can change measured task performance more than swapping models does.
  • Tailscale scopes device-to-device access through a tailnet policy file using tags and grants; a default-deny policy is the recommended starting point rather than allowing all devices to reach all others.
  • Splitting experiments by machine role benefits from an explicit device-tagging scheme in the tailnet policy rather than informal machine nicknames alone.

Porting Claude Code Harness Conventions to GitHub Copilot

The operator wanted a migration reference mapping their existing Claude Code setup onto GitHub Copilot for use at work.

  • GitHub Copilot's closest analogue to a CLAUDE.md is a single repo-root copilot-instructions.md, plus path-scoped .instructions.md files that apply only to matching files via an 'applyTo' field.
  • Instruction precedence is personal > repository > organization for Copilot — the opposite ordering from what might be assumed, and worth checking before relying on repo-level instructions to override a personal preference.
  • VS Code layers its own agent-mode custom-instructions mechanism on top of GitHub's web-level personal/org instructions, so the two need to be configured separately.

Assessing Reproduction Fidelity Against a Paper's Own Artifacts

The operator asked for a delta evaluation between an internal sealed reproduction and what the original paper's authors actually produced and shipped.

  • ACM's artifact badging (Available / Functional / Reproduced) gives a standard vocabulary for how close a reproduction needs to be before it counts as validated, rather than a binary pass/fail.
  • Code availability doesn't predict reproducibility: in one large check of published ML papers, whether the authors released code had no significant relationship with whether independent reproduction actually succeeded.
  • A paper shipping no runnable artifacts at all is common rather than exceptional — roughly 60% of security-focused ML papers in one study included no code to run their own experiments.

Global Workspace Theory as a Lens for Multi-Agent Architectures

The week's automated arxiv triage scored several candidate papers specifically for Global Workspace Theory (GWT) resonance — broadcast mechanisms, central bottlenecks, coalition competition — as one of its scoring voices.

  • GWT models cognition as specialist modules competing for a capacity-limited workspace, with the winning content broadcast to the whole system — that functional pattern (shared blackboard + broadcast step) is what to look for in multi-agent code, independent of whether Baars is ever cited.
  • Most current multi-agent LLM systems rely on message-passing loops rather than an always-on shared-awareness channel, which is the specific gap GWT-inspired architectures are being proposed to fill.
  • 'GWT-implicit' is a useful triage category on its own: a system can exhibit broadcast/bottleneck/coalition behavior functionally without the paper naming Global Workspace Theory at all.

Efficiency Techniques for LLM Agent Inference

The week's arxiv triage included a dedicated 'optimization/efficacy' scoring pass that flagged papers specifically for sampling-cost and decoding-efficiency gains in agent inference.

  • Selective prediction — deferring or abstaining based on the model's own uncertainty — is a recurring way to cut inference cost without giving up accuracy on the cases that actually matter.
  • Trajectory-reduction methods that trim accumulated context/input tokens across an agent's run can meaningfully cut cost; one cited approach reports roughly 40-60% fewer input tokens and 20-35% lower total compute while holding performance steady.
  • Claims of 'zero added inference cost' on agent-efficiency techniques deserve scrutiny — one flagged paper's amortization story was noted as undercut by high run-to-run session variance.
