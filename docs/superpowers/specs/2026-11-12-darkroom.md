> Organising sentence: the lab is a darkroom. Sources go in as grey type, get developed, read, struck out and set into one sheet, and only a sheet that was tested gets the red stamp.

## 1. Rules that frame everything

1. **One family on the site:** Archivo, variable, using its width axis as the voice switch (condensed = labels and stage names, normal = reading, expanded = display). Docs keep a reading face (§4.1).
2. **One colour with meaning:** safelight red `--dn-tested` means "this was tested". Every other surface is warm neutral. The palette comes from the subject (darkroom: warm black, paper, safelight), which is the AI-tells note's (D12) remedy for "near-black plus one accent".
3. **One orchestrated moment:** the homepage frame sequence. Everything else is still, apart from hover and focus feedback (AI tell D13).
4. **One curve:** `cubic-bezier(.19, 1, .22, 1)`, in CSS, in the scroll scrub and inside the frame painter.
5. **One proportional comp:** the root font size scales with the viewport (§4.3), so every `rem` token scales as one layout.
6. **Honesty:** every visible word is approved copy (the Pages tickets, `#16`) or a small structural label. The frame sequence is abstract: bars, never words, never invented titles, numbers or quotes. The only numbers it shows are derived (frame index, stage n of 5).

### 4.3 Root font size

Design width **1440 px** (16 px root there).

```css
html { font-size: clamp(0.9375rem, 0.125rem + 0.9722vw, 1.375rem); }
```

- 1440 px → 16.0 px; floor 15 px from ≈ 1337 px down (so 760–1337 px is a fixed 15 px band: layouts there must be checked); ceiling 22 px from ≈ 2057 px.
- Bounds are in `rem` (the user's default size), not C's `px`, so a browser font-size preference still applies. max/min = 1.47 ≤ 2.5, so text still reaches 200% under zoom (WCAG 1.4.4).
- Media queries use px (they ignore the root). `-webkit-text-size-adjust: 100%`. Never disable zoom.
- Docs in the viewer use `rem` heavily, which would make them scale with the root; §8.3 pins them.

### 4.5 Typographic rules (changes to the old §7)

1. Sentence case everywhere (#16 rule 7). Headings never end in a full stop.
2. **Caps** only in the label, brand and rail roles, i.e. rules whose `font-stretch` is `var(--dn-wdth-label)` or `var(--dn-wdth-ui)`, on ≤ 3 words of chrome. Tracking ≤ 0.08em (C's 0.16–0.22em is cut: it is AI tell D9). Never on headings.
3. Size floor 12 px computed at the 15 px root (so `rem` tokens ≥ 0.8rem). The only exemption is `aria-hidden` art marked `/* type-lint: art */` (the stamp SVG).
4. No hand-typed numbers or `//` prefixes. Only the five method stages are numbered, from array order (AI tell D1). C's section numbers (02–06) are not used.
5. Links: `--dn-text`, underline 1px, `text-underline-offset: 0.22em`, decoration colour `--dn-text-label`, turning `--dn-text` on hover. Row-title and nav links drop the underline at rest; `aria-current="page"` keeps it. Links never turn red.
6. One display moment per page: the h1.

## 5. Layout and spacing

- **Gutter** `--dn-gut`: 2.5rem (40 px at 1440) at ≥ 760 px; `16px` below.
- **Two-column grid** (C's): `--dn-col-label` 24.5rem at ≥ 1100 px, 12rem at 760–1099 px, none below 760 (single column). Column 1 holds a section's h2 and one-line intro (or marginalia); column 2 holds content. Each section starts with a 1px `--dn-rule` hairline across both columns and 9rem (desktop) / 6rem (phone) of space above.
- **Measure** `--dn-measure`: 36rem for running prose.
- **Page max** `--dn-page-max`: 94rem, centred (only bites above ≈ 2057 px, where the root caps).
- **Nav height** `--dn-nav-h`: 3.5rem at ≥ 700 px (sticky), `0px` below 700 px (#70).
- **Spacing scale** (rem, scales with the comp): `--dn-sp-1` .25, `-2` .5, `-3` .75, `-4` 1, `-5` 1.25, `-6` 1.5, `-7` 2, `-8` 2.5, `-9` 3, `-10` 4, `-11` 6, `-12` 9.
- No radius (50% only on the tested mark and stamp). No shadows. No gradients except the vignette baked into frames.
- Breakpoints (px): 700 (nav), 760 (grid), 1100 (label column width). Phone (390 px) is a first-class layout, not a squeezed desktop.
- Shared primitives live in `src/styles/layout.css`: `.dn-page` (gutters, page max), `.dn-grid` with `.dn-grid__label` / `.dn-grid__body`, `.dn-section`, `.dn-register` / `.dn-register__row` (§7.3), `.dn-label`, `.dn-visually-hidden`.

## 6. Motion

- `--dn-ease: cubic-bezier(.19, 1, .22, 1)`; the TS twin is `EASE = [0.19, 1, 0.22, 1]` in `src/lib/darkroom/ease.ts`. No other curve anywhere, except `linear` for opacity fades tied to scroll.
- Durations: `--dn-dur-1` 160ms (hover and focus feedback), `--dn-dur-2` 500ms (caption out), `--dn-dur-3` 1000ms (caption in, 120ms delay), `--dn-dur-4` 1300ms (rail jump scroll).
- **What may move:** (a) the homepage sequence: scroll-scrubbed frames, the hero copy fading and its h1 condensing 125 → 62 over p 0 → 0.07, the rail fill, stage captions swapping, the stamp landing (p 0.905 → 0.95, scale 1.32 → 1, rotate −8deg); (b) hover and focus colour transitions. Nothing else: no scroll reveals, no ambient or `infinite` animation, no marquee, no parallax.
- Motion starts only when `(prefers-reduced-motion: no-preference)` matches, checked in JS (`useReducedMotion`, which subscribes to changes and switches mode without a reload) and in CSS.
- **Reduced motion:** no scrub, no frame baking. The homepage shows the hero copy and a contact strip of five stills (§8.4). The global guard in `base.css` cuts transitions and animations to 0.001ms and sets `scroll-behavior: auto`. Rail-style jumps become instant.

## 8. The frame-sequence engine

### 8.1 Module (`src/lib/darkroom/`, pure TS, no React, no globals)
Port `c.html` lines 349–760 (content, painter) and 840–1002 (live mode) into typed modules. Keep C's timings (`MARKS = [0.06, 0.22, 0.40, 0.585, 0.78]`, `STILL_P = [0.2, 0.34, 0.575, 0.7, 1]`, every `seg()` window), seed `7193`, galley kinds, notes, survivors and page layout.

| File | Exports |

| `scrub.ts` | `createScrub({ read, apply, tau: 0.12 })`: rAF only while settling, `p += (target − p)·(1 − e^(−dt/τ))`; `tweenScroll(y, ms)` with `ease`, cancelled by user input |

| `index.ts` | the runtime entry, loaded with dynamic `import()` |

Behaviour carried over from C and required: render on demand only (an idle page does zero work); bake pauses while `document.hidden`; drawing stops while the stage is off screen (IntersectionObserver); nearest-frame draw with ±2 fallback, then live paint; rebuild after a width change (debounced 220ms), ignoring height changes under 120px (mobile URL bar); the hero h1 line breaks are frozen at full width before it condenses (C's `freezeLines`). New for the SPA: `destroy()` cancels rAF and timers, revokes every blob, closes every bitmap and disconnects observers on route change. No GSAP and no CDN: the scrub, tween and curve are ours (≈ 2 KB).

## 12. Risks
- **The 760–1337 px band** has a fixed 15 px root; display sizes there are the largest relative to width. Check overflow at 760, 1024 and 1100 px.
- **Memory on phones.** iOS Safari caps canvas memory; the LRU, the pixel ceiling and `destroy()` are the defence. If WebKit on a real iPhone stutters, drop to 120 frames below 760 px (one constant).
- **Library after the run.** The library starts after five to six screens of sequence, while #15/#26 say the homepage leads with docs. Mitigations: the skip link, `Browse the library →` in the hero, and the hand-off from stamp to register. Open question in the plan.
- **Archivo for site body text** has no legibility audit like Atkinson's; site body copy is short. Revisit if a reader complains.
- **Archivo arrows**: see §4.2 fallback.
- **Doc `rem` rewrite** touches every doc's CSS; the doc-viewer canary and pixel tests are the guard.
